## 3. Summary of Gaps Identified and Fixed During Audit

1. **Storage Driver Unit Test Resilience**:
   - **Gap**: `StorageService` unit test failed in environments where `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` were populated in `.env`, because it unconditionally created the Supabase client rather than testing the local disk fallback driver.
   - **Fix**: Added optional `{ forceLocal?: boolean }` to `StorageService` constructor in [`apps/api/src/services/storage.service.ts`](file:///home/sam-sepiol/Documents/campaign/apps/api/src/services/storage.service.ts) and passed `{ forceLocal: true }` in [`apps/api/src/__tests__/storage.test.ts`](file:///home/sam-sepiol/Documents/campaign/apps/api/src/__tests__/storage.test.ts). Re-verified: 100% passing.
2. **Upload Test URL Regex Compatibility**:
   - **Gap**: `creator.test.ts` line 398 checked `url.toMatch(/^\/uploads\//)`, which failed when Supabase Storage returned the public CDN URL (`https://...`).
   - **Fix**: Updated assertion to `toMatch(/^(\/uploads\/|https?:\/\/)/)` in [`apps/api/src/__tests__/creator.test.ts`](file:///home/sam-sepiol/Documents/campaign/apps/api/src/__tests__/creator.test.ts). Re-verified: 100% passing.
3. **Hermetic Automated Test Execution against Embedded Postgres**:
   - **Gap**: `apps/api/package.json` ran Vitest directly against whatever was in `DATABASE_URL`. When pointing to the remote Supabase PgBouncer pooler across the internet, high network roundtrip latency triggered Vitest's 5000ms test timeout.
   - **Fix**: Configured `"test": "DATABASE_URL=\"${TEST_DATABASE_URL:-postgresql://postgres:password@localhost:5432/campaigns}\" vitest run --fileParallelism=false"` in [`apps/api/package.json`](file:///home/sam-sepiol/Documents/campaign/apps/api/package.json) so tests run hermetically against local embedded Postgres in under 30 seconds.
4. **Expo-Image Replacement in Creator Dashboard & Visuals**:
   - **Gap**: [`apps/mobile/src/app/creator/dashboard.tsx`](file:///home/sam-sepiol/Documents/campaign/apps/mobile/src/app/creator/dashboard.tsx) and [`apps/mobile/src/app/create/[draftId]/visuals.tsx`](file:///home/sam-sepiol/Documents/campaign/apps/mobile/src/app/create/[draftId]/visuals.tsx) imported legacy React Native `Image` instead of `expo-image`.
5. **Centralized Demo Disclosures, 4-Tab Bottom Navigation & Profile Photo (Decision 41)**:
   - **Gap**: Repetitive `DemoDataBadge` instances cluttered campaign cards and receipts; bottom navigation had 5 tabs crowding navigation; and profile avatar updates lacked client/server host validation.
   - **Fix**: Centralized demo disclosures exclusively to 3 canonical locations (About, FAQ, Terms) and removed all `DemoDataBadge` instances. Set `<Tabs.Screen name="profile" options={{ href: null }} />` to provide a spacious 4-tab bar (`Home`, `Explore`, `Create`, `Activity`) while routing Profile through the sticky top header avatar. Added `isAllowedStorageUrl` validator in `packages/shared` and validated host in `PATCH /me`. Added 144dp avatar with photo picker bottom sheet. Re-verified: 100% passing.
6. **Button Action Arrow Invariants & Universal Tab Header Avatar (Decision 42)**:
   - **Gap**: "Back This Campaign" erroneously had a trailing arrow; Profile was only reachable from the Home tab header avatar, risking navigation dead ends on other tabs.
   - **Fix**: Enforced that only "View Details" receives the trailing arrow; "Back This Campaign", "Follow progress", and "View final report" have NO arrow. Added `HeaderAvatar` across all four tab screens (`Home`, `Explore`, `Create`, `Activity`) to guarantee single-tap Profile access from anywhere in primary navigation. Formally logged 4 bottom tabs as a deliberate, owner-approved deviation.
